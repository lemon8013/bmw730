# 07 数据模型与数据库设计

## 核心表
### tool_category
`id, code, name, slug, icon, description, sort_order, status, created_at, updated_at, deleted_at`

### tool
`id, code, name, slug, category_id, icon, summary, description, keywords, component_key, execution_mode, status, sort_order, created_at, updated_at, deleted_at`

### tool_version
`id, tool_id, version, changelog, status, component_key, minimum_frontend_version, published_at, created_at, updated_at, deleted_at`

### tool_access_policy
`id, tool_id, subject_type, enabled, daily_limit, rate_limit_per_minute, created_at, updated_at`

唯一性：
- tool.code 在软删除范围内唯一
- tool.slug 在软删除范围内唯一
- category.code/slug 同理
- tool_version(tool_id, version) 唯一
- policy(tool_id, subject_type) 唯一

### tool_usage_event
保存原始使用事件；高增长环境允许后续按月分区。分区不是当前阶段的强制实现。

### tool_usage_daily
保存聚合数据，`(stat_date, tool_id)` 唯一。

## ID
所有业务 ID BIGINT + Snowflake；API JSON 字符串。

## 时间
UTC。

## 软删除
业务表使用 deleted_at；统计事件默认 append-only。

## 与后台
工具管理权限复用现有 RBAC，不引入 tenant_id。
