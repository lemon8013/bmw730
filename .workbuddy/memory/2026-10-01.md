## 踩到并修掉的 3 个真问题（后续务必注意）

1. **SQLAlchemy 会给单列整型主键自动加自增** —— 首次迁移产生了 69 个序列
   （`DEFAULT nextval(...)`），直接违反 Snowflake ID 约定。修复：所有单列 BIGINT
   主键加 `autoincrement=False`。注意 PK 同时是 FK 的 4 列不会被自动加，所以数量是
   73-4=69。
2. **Alembic 会静默跳过 `use_alter` 外键** —— `op.create_table` 内联的
   `fk_tool_current_version` 在运行时没被创建（tool 在 840 行、tool_version 在
   1093 行）。修复：从 create_table 中移除，改为在 tool_version 建表后显式
   `op.create_foreign_key`。这是 `tool` ↔ `tool_version` 循环外键。
3. **`metadata` 列名与 SQLAlchemy 保留属性冲突** —— 8 张表有该列。修复：数据库列名
   保持 `metadata`，Python 属性改为 `metadata_payload`。

## Phase 2：后端业务实现收尾 + PostgreSQL 初始数据（Seed）实施

### 1. 修掉路由「重复段」根因（真 bug）

`main.py` 的挂载前缀与各 router 内部路径**都**写了模块段，导致
`/admin/users/users`、`/admin/departments/departments`、`/platform/auth/auth`、
`/blog/articles/articles`、`/analytics/events/events`、`/tools/catalog/tools` 等。

- 解析 spec 各文档的 `Base`：`02-Admin` = `/api/v1/admin`，`03/04/05/06/08` = `/api/v1`。
- 修法：**只改 `main.py` 的挂载前缀**（`/admin`、``、`/tools`、`/blog`、`/analytics`、
  `/files`、`/jobs`、`/search`），仅 `blog/comments` 需改内部路径（`/pending`→`/comments/pending` 等）。
- 补齐此前**未挂载**的 `platform/tasks`、`platform/achievements` 路由。
- 结果：OpenAPI 157 → **162** 条路径，重复段归零。

### 2. Seed 包（`app/scripts/seed/`）

模块划分：`catalog`（纯数据）/ `system_seed`（流程）/ `test_seed` / `helpers`
（`ensure_row` 幂等写入）/ `runner`（事务+环境变量）/ `report` / `cli`。

- 命令：`python -m app.scripts.seed [--mode=system|test] [--runs=N]`；退出码 0/1/2。
- 幂等：只按稳定业务键 `find_one`（字符串 lower 比较 + 过滤 `deleted_at`），不存在才 INSERT；
  已有行**直接返回，不 UPDATE**。一次 run = 一个事务，异常整体 rollback。
- 安全：管理员密码只从 `VCTN_SEED_ADMIN_PASSWORD` 读，缺失即 `SEED_ADMIN_PASSWORD_REQUIRED`；
  复用 `hash_password`（pwdlib Argon2）；**不重置已存在管理员密码**。
- **权限：冻结矩阵为唯一权威** —— `catalog.MATRIX_PERMISSIONS`（64 条，来自
  `11-权限矩阵.md`）+ `RUNTIME_EXTRA_PERMISSIONS`（9 条代码里实际 require 但矩阵没有的码，
  逐条登记 BLOCKERS）。合计 73 条业务权限。
- **端点权限：AST 扫描真实依赖** —— `collect_route_guards()` 遍历
  `app.main._BUSINESS_ROUTERS`，对每个 `APIRoute.endpoint` 用
  `inspect.getsource` + `ast` 提取 `require_permission(...)` 字面量，把端点权限节点
  `parent_id` 挂到其**唯一**守护业务权限上（107 条）。

### 3. 关键坑（务必记住）

1. `app.routes` 在本 FastAPI 构建里是 `_IncludedRouter`，**没有 `APIRoute`**；
   枚举端点必须用 `app.openapi()["paths"]`。
2. **`router.__module__` 会回退到 `fastapi.routing`**（实例没有该属性）——
   想拿定义模块要用 `route.endpoint` 或 `inspect.getsource`。
3. `tests/conftest.py` 里 `os.environ["VCTN_ENV_FILE"]=""`，所以跑脚本读
   `.env` 时必须把 CWD 放在 `vctn-api/`。
4. **`aicoding/spec/` 目录名是双重编码乱码**，读之前先 `cp` 成 ASCII 名。

### 4. 修掉「幽灵表」`sys_export_task`（违反禁止自行建表）

`app/admin/export/model.py` 自建了 DDL 中不存在的 `sys_export_task`，导致
`Base.metadata` 80 表/772 列、`tests/integration/test_schema.py` 5 条失败，且导出功能
运行时会 `relation does not exist`。已改为复用冻结表 `sys_export_job`
（`ExportJob = SysExportJob`），DTO/仓储/路由字段对齐真实列（`export_type` /
`filter_json`；移除无对应列的 `progress` / `updated_at`；删死代码
`LogExportTriggerResponse`）。修后：**79 表 / 761 列 / 79 PK / 82 FK，与 DDL 零差异**。

同时把 `tests/unit/test_app_wiring.py` 的断言从「挂载前缀不得重复」改为
「同一 METHOD+path 不得被两个 router 声明」+「路径不得有连续重复段」。
