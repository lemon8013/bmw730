## 踩到并修掉的 3 个真问题（后续务必注意）

1. **SQLAlchemy 会给单列整型主键自动加自增** —— 首次迁移产生了 69 个序列
   （`DEFAULT nextval(...)`），直接违反 Snowflake ID 约定。修复：所有单列 BIGINT
   主键加 `autoincrement=False`。注意 PK 同时是 FK 的 4 列不会被自动加，所以数量是

   `fk_tool_current_version` 在运行时没被创建（tool 在 840 行、tool_version 在
   1093 行）。修复：从 create_table 中移除，改为在 tool_version 建表后显式
   `op.create_foreign_key`。这是 `tool` ↔ `tool_version` 循环外键。
3. **`metadata` 列名与 SQLAlchemy 保留属性冲突** —— 8 张表有该列。修复：数据库列名
   保持 `metadata`，Python 属性改为 `metadata_payload`。

## Phase 3.1：登录 422 排查 → 修掉后端 N+1（11 秒）与前端登录阻塞

### 1. 用户报的 422 是「缺少 Content-Type: application/json」

逐一复现确认（`POST /api/v1/admin/auth/login`）：

| 请求方式 | 结果 |
| --- | --- |
| JSON body + `Content-Type: application/json` | **200** |
| 无 Content-Type（curl `-d` 默认 form-urlencoded） | 422 `model_attributes_type` |
| `Content-Type: application/x-www-form-urlencoded` | 422 `model_attributes_type` |
| 空 body + JSON 头 | 422 `Field required` |
| 缺 password 字段 | 422 `loc=["body","password"]` |
| 密码错误 | 401 `401001` |
| GET（浏览器直接打开地址） | 405 |

→ 前端 axios 已默认带该头，**前端不受影响**；是手工调试工具没设头。

### 2. 但顺带查出真 bug：登录其实一度超时（这个才是要命的）

浏览器 UI 登录报「请求超时，请稍后重试」（20s 客户端超时），按钮一直 disabled。

**根因：`/admin/permissions/resources` 有 N+1 + 伪分页**
- `PermissionService.list_resources` 先 `list_all()` 取**全部 362 行**，
  再对**每一行**调 `_to_response` → 每行单独查一次 `fields_of()`，
  即 **1 + 362 = 363 次数据库往返**，最后在 Python 里 `items[offset:offset+limit]` 切片。
- 实测：`page_size=100` 单次 **11111ms**；前端 `loadFieldPolicies()` 要遍历 4 页
  → 总计约 44s，必然超过 20s 超时。

**修法（后端，根治）**
- 仓储新增 `list_page(offset, limit)`（DB 层 LIMIT/OFFSET）、`count_all()`、
  `fields_of_many(ids)`（一条 `IN (...)` 查询 + Python 分组）。
- `list_resources` 改为：count + 取本页 + 一次取本页字段策略 = **恒定 2 次查询**。
- 抽出同步的 `_build_response(row, fields)`，保留 `_to_response` 给单条详情用。
- 效果：`page_size=100` **11111ms → 549ms**；遍历全部 362 行 **~44000ms → 673ms**（约 20 倍）。
- 回归：`ruff` 全绿、`pytest` **136 passed**。

**修法（前端，防御）**
- `loadFieldPolicies()` 改为**不阻塞** `loadSession()`（`void` 后台加载）：
  字段策略只是叠在本地 deny-list 之上的增强，慢或 403 都不该拖死或搞挂登录。
- `listAllPermissionResources()` 页大小提到 200，并改成「本页不满 / 返回空」即停，
  避免后端 `total` 异常时死循环。
