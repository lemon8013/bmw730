## 宝塔部署启动报错（uWSGI + pydantic）
- 报错：`ImportError: cannot import name 'BaseModel' from 'pydantic'` +
  uWSGI `unable to load app 0 (mountpoint='') (callable not found or import error)`。
- **两个独立根因**：
  1. **venv 跨平台拷贝**：把开发机 Windows 的 `.venv` 上传到 Linux，`pydantic_core` 是 `.pyd`，
     Linux 导入失败，表现为 pydantic 里拿不到 `BaseModel`。唯一修法 `rm -rf .venv` 重建，
     不要单独 `pip install pydantic` 补（会打乱锁定组合：
     fastapi 0.142.2 / pydantic 2.13.5 / pydantic_core 2.46.5 / uvicorn 0.54.0）。
  2. **uWSGI 跑不了 ASGI**：FastAPI 是 ASGI 三参数协程签名，uWSGI 按 WSGI 找 callable。
     项目依赖里没有 gunicorn/uWSGI，启动器就是 uvicorn。
- 文档已补：`docs/DEPLOY-CENTOS.md` 新增 **第 8 节「宝塔面板（BT Panel）部署」**
  （8.1 不用 uWSGI / 8.2 建 venv 与验收 `pydantic.VERSION==2.13.5` / 8.3 uvicorn 启动 + systemd /
  8.4 站点根 + `/api/` 反代 + **宝塔反代不带 SPA fallback，需手写 `try_files $uri $uri/ /index.html`**），
  排障速查表也加了这两条。
- 部署路径：服务器 `/www/wwwroot/vctn/vctn-api`（Python 3.12，满足 requires-python >=3.11）。
- 注意：用户在对话里贴出了种子/管理员口令，**已在回复中提醒视为泄露并更换**。
- **续**：用户又报 `nohup: failed to run command '.../.venv/bin/uwsgi': No such file or directory`
  —— 宝塔「Python 项目」给项目生成的是 uWSGI 启动命令，而锁文件里只有 uvicorn（无 uwsgi/gunicorn）。
  **处理：面板里删掉/停用该 Python 项目**，后端改用：A 命令行 nohup uvicorn 验证 /
  B 宝塔「进程守护管理器(Supervisor)」填运行目录+uvicorn 绝对路径 / C systemd（sed 替换
  /srv/vctn/app → /www/wwwroot/vctn）。三者只能选一个，别同时跑（端口冲突 + 调度器重复执行）。
  文档 8.3 已补全这三种方式。
- **续 2**：`AttributeError: module 'platform' has no attribute 'system'`（栈里是 uuid.py → click → uvicorn）。
  根因：**后端有业务包 `app/platform/`**，`platform` 与标准库同名。Python 把启动目录放 sys.path[0]，
  一旦工作目录是 `.../vctn-api/app`（或 `python app/main.py`、PYTHONPATH 指到 app/），
  `import platform` 就拿到业务包 → 标准库 uuid 崩。**规则：启动目录永远是 `vctn-api`，命令
  `uvicorn app.main:app`**；宝塔/gunicorn 的 chdir 也填 vctn-api；禁用 `python app/main.py`。
  自检：`.venv/bin/python -c "import sys, platform; print(sys.path[0]); print(platform.__file__)"`
  第二行必须是 `/usr/lib/python3.12/platform.py`。
  文档已补：排障速查表一行 + **8.5 节「工作目录必须是 vctn-api，不能是 vctn-api/app」**。
