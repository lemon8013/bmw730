## 后端真 bug：工具执行一直 500
- 根因：`app/tools/usage/service.py::record()` 传了 `id=new_id()`，而
  `ToolUsageRepository.add_event()` 内部也注入 `id=new_id()` →
  `TypeError: ToolUsageEvent() got multiple values for keyword argument 'id'`。
- 修复：移除 service 里冗余的 `id=new_id()`（id 由 repository 统一生成），
  并删掉不再使用的 import。
- 复现脚本：`vctn-api/.devtools/repro-tool-execute.py`（直连 DB 调 service，
  比看 HTTP 500 快得多；注意要 import 模型模块否则 FK 解析失败）。
- 修复后 17 个组件全部执行成功，后端 136 测试全过。

## 勘查：工具可见性 + 用量统计（登记 BLOCKERS B-34/B-35/B-36）
用户问「后台怎么设谁能看工具」「在哪看使用频率」，勘查结论：

### 可见性（判定链在 `app/tools/access/service.py::ToolAccessService.resolve`）
1. `status != ACTIVE` → 404（admin `/tools` 上线/下线控制，字典 `TOOL_STATUS`
   = ACTIVE/DRAFT/OFFLINE/DEPRECATED；`active_tools()` 与 `tools_of_category()`
   都过滤 ACTIVE，所以下线即刻消失）。
2. `is_guest` → GUEST 策略，否则 USER 策略。
3. **策略行不存在时 `enabled = not is_guest`** → 游客默认禁止、登录用户默认允许。
4. 再查 enabled 与三项配额（配额为 null 时回落全局
   `TOOL_GUEST_DAILY_QUOTA` / `TOOL_USER_DAILY_QUOTA`）。
- **粒度只有 GUEST / USER 两档，做不到指定用户或角色**：`tool_access_policy`
  唯一约束 `(tool_id, subject_type)`，无 subject_id，且 backend 正则锁 `^(GUEST|USER)$`。
  属冻结 DDL 限制 → B-35。
- **坑**：`POST /admin/tools` 新建工具不自动建策略行 → 新工具游客不可用、仅登录用户可用。
  seed 则给每个工具建了 GUEST+USER 且 enabled=True。

### 用量统计（三条链都不通/read不到）
- `tool_usage_event`（29，实时）→ `tool_usage_daily`（18，同事务写入）✓
- `tool_popularity_daily`（**0 行**）：唯一入口 `POST /tools/statistics/refresh`
  需业务用户身份，**且没有任何定时任务调它** → 热门榜 `/tools/popular` 恒 `[]` → B-36。
- 管理后台 `/tools/statistics` 首屏调 `/tools/usage/recent` → Operator 401 →
  再触发 `/admin/auth/refresh` 401 → **被踢回登录页**（实测确认，同 §七 成长缺口）→ B-34。
- 要看数据目前只能直连库查 `tool_usage_event` / `tool_usage_daily`。
