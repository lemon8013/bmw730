## 修 bug：可见性下拉一直「加载中」（前端）

`ToolListPage.vue::onChangeVisibility` 把 `savingVisibilityId` 置位后**没有 finally 复位**，
而列的 `:loading` 只由它驱动 —— 第一次切换后下拉永久转圈且被禁用，无法再改。
修法：`finally { await reloadVisibility(); savingVisibilityId.value = '' }`，并把比较统一为
`String(row.id)` / `String(tool.id)`。其他页面的 submitting ref 都规范用了 finally，仅此一处漏。
浏览器实测：连切两次（PUBLIC→REGISTERED→PUBLIC）均 LOADING=false 且文本正确。

## 环境与坑

- **`uvicorn --reload` 在本机不生效**：改完后端代码必须 `taskkill` 掉 8000 端口进程再手动重启，
  否则 OpenAPI 里看不到新路由（实测踩了两次，一次返回 404、一次返回旧窗口数据）。
  建议启动时不加 `--reload`。
- 后端用 `Bash run_in_background` 常驻（8000）；`mint_token.py` 需要 `PYTHONPATH=.` 才跑得起来。
- **子 shell 后台 `(cmd &)` 同样会被回收**，只有 Bash 工具的 `run_in_background=true` 可靠。
- Element Plus 确认框（`useConfirm`）的主按钮文案是「**确认**」不是「确定」，自动化点按钮别写错。
- 执行端点真实路径是 `/api/v1/tools/runtime/execute/{tool_id}`（不是 `/api/v1/runtime/...`），别再 404 误判。
- admin-web 浏览器验证：`scripts/browser-verify.sh` 注入 token 后用 **`goto`**（`open` 会开新会话丢 sessionStorage）。
