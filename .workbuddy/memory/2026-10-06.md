## 登录输入框「两个颜色」修复（2026-10-06 下午）
- 现象：admin 登录页输入框出现两种颜色。实测浅/暗色静态样式均统一（wrapper 白底浅灰描边；
  暗色 wrapper=卡片=#171B21），根因是 **Chrome/Edge `:-webkit-autofill` 给记住的账号密码
  输入框强制染淡黄/淡蓝底**，盖掉我们的白色。
- 修复：三站 `src/styles/index.css` 各加一段 autofill 覆盖——`box-shadow` 双层
  （1px 边框 + 1000px bg-surface 内阴影盖底色）、`-webkit-text-fill-color` 锁文字色、
  focus 态边框换 brand 色、`transition: background-color 99999s` 防 UA 动画回弹。
  浏览器验证三站登录页各注入 2 条 autofill 规则、0 console error。
- **返工**：上一版 autofill 修复把 1px 边框画在了 `.el-input__inner` 上（box-shadow 内含
  `0 0 0 1px` 层），而 Chrome 一旦标记过 autofill（值清空也不解除）伪类持续命中 →
  聚焦时 inner 灰框 + wrapper 蓝框叠成**双圈**（用户截图确认）。
  已改为 autofill 规则**只保留 1000px 背景层、不画边框**，边框唯一归
  `.el-input__wrapper` 管；三站同步替换并截图复验聚焦态单框。
- 教训：`:-webkit-autofill` 状态会驻留；给 inner 加任何 box-shadow 层都会与 wrapper
  描边叠加，autofill 覆盖里只放背景色。
- **第三次排查「红线/两个输入框」**：用户截图 error 提示下方多一条红色横线。
  复现后三重验证：① DOM 只有 1 error/2 form-item/2 input，无多余元素；
  ② 伪元素扫描只有必填星号；③ 受控 Chrome 渲染截图（含 zoom=3 放大）**无横线**。
  结论：红线来自用户浏览器环境层（最大嫌疑：中文输入法的组合串下划线，搜狗系为红色；
  或密码管理器/翻译扩展），不是页面代码。已请用户无痕模式/切英文输入法验证。
  教训：判断"页面外的线"先看受控浏览器截图与 DOM 是否一致。
- **第四次返工「密码框内嵌小框」**：根因 = 1000px inset box-shadow 涂层的**圆角抗锯齿缝隙**
  在 inner 边界形成可见细线（浏览器渲染伪影，资料：Autofill-CSS-Styling-Control 证实
  box-shadow 方案必有 corner gaps，transition 冻结法 100% 无缝）。
  最终方案：**去掉全部 box-shadow，只用 `transition: background-color 999999s` 冻结 UA 底色**
  （三站已替换：-webkit-text-fill-color 锁文字色 + 无尽过渡冻结背景）。
  Chrome 新版对 box-shadow 遮盖本就不可靠，纯 transition 是当前业界共识。

## admin 登录失败排查与解决（2026-10-06 晚）
- 现象：用户报"登录失败"。排查链路：
  ① 四服务在线、/health /ready 均 ok（PG+Redis ok）；
  ② POST /api/v1/admin/auth/login 传错用户返回标准 401001 → 接口正常；
  ③ asyncpg 直连查 `sys_user`：`admin` 账号 ACTIVE、failed_login_count=0、locked_until=null，
     **last_login_at 刚更新**（说明认证那一跳成功过）；
  ④ 自签 JWT 验证登录后链路 **/auth/me、/auth/permissions 都 200**；
  ⑤ 把 access token 注入 sessionStorage（key：`vctn.admin.access_token` /
     `refresh_token` / `access_expires_at`）后进主界面，菜单/用户信息全部正常、0 console error；
  ⑥ Redis 无 login 限流残留（限流 10 次/60s，无关）。
  → **结论：后端与前端都没坏，是密码不匹配**（seed 密码由 `VCTN_SEED_ADMIN_PASSWORD` 注入、明文不留存）。
- **解决**：一次性脚本用后端同一套 hasher（`pwdlib` `hash_password`）重写 admin 密码，
  并 `failed_login_count=0、locked_until=null、must_change_password=true、password_changed_at/updated_at=now、
  password_expires_at=+90d`。新密码 **`Vctn#Admin2026`**（满足 ≥12 位+大小写+数字+特殊）。
  浏览器端到端登录验证通过（登 200，约 1s），登录后跳 `/change-password` 强制改密页。
- **坑（重要，勿踩）**：用 `get_settings()` 自签 JWT 会因为在**仓库根目录**运行时 pydantic 找不到
  `vctn-api/.env` 而拿到空 `AUTH_JWT_SECRET` → `resolved_jwt_secret` 生成**随机临时密钥** → 所有自签 token 401。
  诊断脚本必须 `dotenv_values('vctn-api/.env')` **直接读原始密钥**，不要依赖 Settings 的 env_file 解析。
- Git Bash 的 `/tmp` 与 Windows Python 看到的路径不一致，跨工具传临时文件要用仓库内相对路径。

## 输入框聚焦蓝色光晕修复（2026-10-06 22:16，勿回退）
- 现象：多个输入框聚焦/激活时边框外有蓝色光晕，右端露出一块蓝色（用户截图红框标注）。
- 根因：全局焦点环 `:focus-visible { box-shadow: var(--vctn-ring) /* 0 0 0 3px brand */ }`
  命中了 `.el-input__inner`（内部原生 <input>）——DOM 焦点在 inner 上而非 wrapper。
  inner 是矩形，3px 光环从 wrapper 圆角描边下漏出，右端最明显。
- 修复：三站 index.css 在 :focus-visible 后追加排除——
  `.el-input__inner:focus-visible, .el-textarea__inner:focus-visible { box-shadow: none; border-radius: inherit }`。
  边框唯一归 wrapper 管（原则同 autofill：不往 inner 上画东西）。
- 验证：聚焦时 inner boxShadow=none、规则已注入；截图确认聚焦框只剩一圈蓝色描边；0 console error。
- 教训（并入 autofill 教训）：**全局 `:focus-visible` 焦点环必须排除 EP 的 inner input/
  textarea**——凡是画在 inner 上的 box-shadow 都会从 wrapper 圆角下漏光。
