## tools-web 补上注册 / 登录（此前完全没有会话）

用户反馈「tool 页面没有注册登录的地方」。tools-web 原本是纯匿名门户，没有任何会话机制。

- 新增：`src/types/auth.ts`、`src/api/credentials.ts`（sessionStorage，key 前缀 `vctn.tools.`）、
  `src/api/session.ts`（单飞刷新 + 会话过期回调）、`src/api/auth.ts`、`src/stores/auth.ts`、
  `src/pages/LoginPage.vue`（登录 / 注册 tab）、`src/components/UserMenu.vue`（头部用户区）。
- 修改：`src/api/client.ts` 请求拦截器自动带 Bearer（并在临近过期时主动刷新），
  响应拦截器 401 → 强制刷新后重试一次；`src/router/index.ts` 加 `/login`（放在 AppLayout **之外**，
  避免带目录导航）；`AppLayout.vue` 头部右侧挂 UserMenu；`main.ts` 冷启动 `auth.restore()`；
  `src/api/endpoint.ts` 抽出 `apiBaseUrl`，避免 client ↔ session 循环依赖。
- 登录页支持 `?redirect=`（只接受以 `/` 开头且非 `//` 的同站路径）；注册成功后**自动登录**
  （注册接口不签发会话）。
- 后端平台端认证端点本来就齐全：`/api/v1/auth/register|login|logout|me|refresh|change-password`。

### 两个后端既有 Bug（都是加登录才暴露出来的）

1. **`RateLimitService` 遇 Redis 故障直接 500**。契约写得很清楚（`OptionalRedisDep` 的文档：
   "an endpoint that needs them must still serve its business purpose when Redis is unavailable"），
   但 `check` / `enforce` / `consume_quota` / `remaining_quota` 全都裸 await Redis。
   已改为 fail-open：新增 `_consume` / `_read` 私有方法捕获 `aioredis.RedisError` + `OSError`，
   返回 `None` 表示不可用，调用方降级为「不限流 / 配额满额」并 `logger.warning`
   （只记异常类型，**不记 key**，key 里含 IP / user_id）。
2. **`app/shared/auth/identity.py` 从错误的模块导入 `BizUserSession`**
   （`app.platform.auth.model` 是 Phase 0 占位文件，里面一个类都没有；真正的定义在
   `app.platform.users.model`）。后果：**登录能成功，但任何需要解析平台身份的端点全部 500**
   （`/auth/me`、`/tools/recent` …）。已改为延迟导入 `app.platform.users.model`
   （`BizUser` 本来就在顶部从那里导入，不要重复导入）。

### playwright-cli 使用坑（本机）

- **浏览器会话不能跨 Bash 调用**：上一个调用里 `open` 的会话，到下一个调用就
  `Browser 'default' is not open`。必须把 open → 操作 → 断言写在**同一条** bash 命令里。
- **element ref 跨页面失效**：页面跳转后 `e26` 指的是新页面的第 26 号元素，不是原来那个输入框。
  跳转后必须重新 `snapshot` 取 ref（我因此误点了工具卡片一次）。
- 跑 `browser-verify.sh` 前先 `playwright-cli close`，否则脚本会卡住被 SIGTERM。
