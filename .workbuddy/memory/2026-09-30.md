## 负责人新增要求：后端配置集中化（已完成）

负责人在 Phase 1 期间追加要求：**「后端所有的配置放在一个配置文件中，不要在代码中硬编码」**。

### 审计结论
Phase 0 已把主要配置集中在 `app/core/config.py::Settings` + `.env`（`alembic.ini` 的 `sqlalchemy.url` 也已留空、由 `migrations/env.py` 从 Settings 注入，未硬编码凭据）。仍硬编码在基础设施代码里的**运维参数**已全部收敛：

| 原硬编码位置 | 收敛为 Settings 字段 |
|---|---|
| `engine.py` `pool_pre_ping=True` | `DB_POOL_PRE_PING` |
| `engine.py` `echo=APP_DEBUG` | `DB_ECHO_SQL`（`None` = 跟随 APP_DEBUG，保持原行为） |
| （新增连接池显式项） | `DB_POOL_SIZE` / `DB_MAX_OVERFLOW` / `DB_POOL_TIMEOUT_SECONDS` / `DB_POOL_RECYCLE_SECONDS`（默认值 = SQLAlchemy 默认，行为不变） |
| `redis/client.py` `encoding` / `decode_responses` | `REDIS_ENCODING` / `REDIS_DECODE_RESPONSES` |
| （新增） | `REDIS_MAX_CONNECTIONS` / `REDIS_SOCKET_TIMEOUT_SECONDS`（None = 库默认） |
| `main.py` CORS `allow_credentials/methods/headers/expose_headers` 字面量 | `CORS_ALLOW_CREDENTIALS` / `CORS_ALLOW_METHODS` / `CORS_ALLOW_HEADERS` / `CORS_EXPOSE_HEADERS`（新增 `cors_methods/cors_headers/cors_exposed_headers` 解析属性） |
| `logging.py` `_LOG_FORMAT`、级别、输出流 | `LOG_FORMAT` / `LOG_LEVEL`（空 = 跟随 APP_DEBUG）/ `LOG_DATE_FORMAT` / `LOG_STREAM`（新增 `resolved_log_level`） |
| `middleware.py` 头名与长度 128 | `TRACE_ID_HEADER` / `REQUEST_ID_HEADER` / `TRACE_ID_MAX_LENGTH`（中间件从 `request.app.state.settings` 读取，正则按长度 lru_cache） |
