## 负责人追问：改为「IP / 端口 / 用户名 / 密码」分字段配置（已完成）

负责人明确：**不要填 URL，要填 ip、端口、用户名、密码**。

### 实现
- 新增字段：`DB_HOST / DB_PORT(5432) / DB_NAME / DB_USER / DB_PASSWORD`；`REDIS_HOST / REDIS_PORT(6379) / REDIS_DB(0) / REDIS_USERNAME / REDIS_PASSWORD`。
- 新增属性 `database_url` / `redis_url` 负责组装驱动 URL：凭据 `urllib.parse.quote(safe="")` 转义；IPv6 自动加 `[]`。**`DATABASE_URL` / `REDIS_URL` 保留为可选覆盖项**（Phase 0 明确要求 Settings 必须支持它们），显式填写时优先级更高。
- 新增 `missing_database_fields`：填了 `DB_HOST` 但缺 `DB_NAME`/`DB_USER` 时**只告警不中断启动**（否则负责人边填 `.env` 边跑测试会被卡死）。
- `migrations/env.py` 在未配置时抛清晰的 RuntimeError（含缺失字段名）。

### 途中发现并修复的两个真问题
1. **空值直接崩溃**：`.env` 模板里 `DB_ECHO_SQL=` / `REDIS_MAX_CONNECTIONS=` / `REDIS_SOCKET_TIMEOUT_SECONDS=` 为空串，pydantic 无法把 `''` 解析成 `bool|None` / `int|None`，`Settings()` 直接 ValidationError。→ 新增 `@model_validator(mode="before")` **「空值视同未提供」**（空=用默认值），这是 `.env` 场景的正确语义。副作用：字符串字段的空校验变得不可达，已删除 `TRACE_ID_HEADER`/`REQUEST_ID_HEADER` 的空值校验并在 docstring 注明。
2. **测试会读取开发者真实 `.env`**（pydantic-settings 的 env_file 相对 cwd）。负责人填好 `.env` 后，`/ready` 类测试会真的去连远程 PG/Redis，既不可复现也可能挂起。→ 新增 `VCTN_ENV_FILE` 环境变量（空值=不加载 dotenv）；`tests/conftest.py` 在导入任何 app 模块**之前**置 `VCTN_ENV_FILE=""` 使测试环境隔离；新增 `live_settings` fixture 用 `Settings(_env_file=".env")` 显式读取真实配置供 readiness 测试使用。
