# 00-需求冻结确认表

> 状态：已冻结  
> 版本：V1.0  
> 技术基线：Python + FastAPI

## 1. 12 项核心决策

| # | 决策项 | 最终方案 |
|---|---|---|
| 1 | 部门管理员数据范围 | 自己所在部门 + 所有下级部门 |
| 2 | 用户角色数量 | 支持多个角色，权限取并集 |
| 3 | 角色继承 | V1 支持 |
| 4 | 页面与菜单关系 | 一个菜单可以关联多个页面 |
| 5 | 权限修改生效 | 立即生效 |
| 6 | 踢下线 | 单个 Session + 全部 Session |
| 7 | 超级管理员被踢 | 不允许任何管理员踢超级管理员 |
| 8 | 用户删除 | 禁用 + 逻辑删除 |
| 9 | 密码策略 | 12 位；大小写+数字+特殊字符；最近 5 次不能重复；90 天修改；5 次失败锁 30 分钟；管理员重置后首次登录必须修改 |
| 10 | MFA 强制 | 支持按角色 + 按用户强制 |
| 11 | 日志保存 | Access 30 天；Security 180 天；Operation 180 天；Audit 2 年；Application 30 天 |
| 12 | 日志脱敏 | 手机号 138****1234；邮箱 abc***@example.com；Token 仅前 6 位；密码和 MFA Secret 禁止记录 |

## 2. 数据范围

部门管理员默认数据范围为 `DEPARTMENT_CHILDREN`：

```text
当前部门
  └── 所有下级部门
```

## 3. 多角色

用户与角色为多对多关系。最终权限为所有有效角色权限的并集。

## 4. 角色继承

V1 支持角色继承。必须检测循环继承。

## 5. 页面与菜单

一个菜单可以关联多个页面。页面访问权限由后台管理平台配置，前端动态生成路由/菜单；后端 API 权限仍是最终安全边界。

## 6. 权限立即生效

权限修改后立即生效，不要求用户重新登录。必须设计缓存失效/权限版本机制。

## 7. Session

支持单 Session 撤销和全部 Session 撤销，并显示在线状态、登录时间、最后活跃时间、IP、User-Agent、设备等。

## 8. 超级管理员保护

非超级管理员不得撤销超级管理员 Session，不得通过普通用户管理接口修改超级管理员认证状态。

## 9. 用户状态

用户支持：

- 正常
- 禁用
- 逻辑删除

删除采用 `deleted_at`。

## 10. 密码

密码使用安全哈希，推荐 Argon2id。密码不得进入任何日志、审计 before/after 或 API 响应。

## 11. MFA

MFA 使用可扩展 Provider。强制策略支持角色级和用户级，用户级优先于角色级。具体 V1 Provider 另在技术设计阶段明确，不在本文件擅自冻结。

## 12. 日志

日志分类和保存周期固定。Audit Log 采用追加原则，普通业务人员不得修改或删除。

## 13. 脱敏

- 手机：`138****1234`
- 邮箱：`abc***@example.com`
- Token：仅保留前 6 位
- 密码：禁止记录
- MFA Secret：禁止记录

## 14. 其他已冻结基线

- 不支持多租户，不使用 `tenant_id`
- 后端 Python + FastAPI
- PostgreSQL + SQLAlchemy + Alembic + Redis
- BIGINT + Snowflake
- JSON 中 ID 字符串化
- UTC 时间
- snake_case 数据库命名
- 页面、菜单、按钮、API、字段、数据范围权限
- 字典与系统参数分离
- Trace ID / Request ID 全链路传播
